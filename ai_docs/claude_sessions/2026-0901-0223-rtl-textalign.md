# Session: Closing the RTL text-align divergence

**Session ID:** session_01HFQHJembyEppoKJCujVjga
**Date:** 2026-09-01, ~02:23
**Branch:** master
**Follows:** `2026-0901-0051-alignment-coverage.md`

Continuation of the previous session's backlog item: **"`AlignStart` is `left`,
not `start`, on both DOM targets."** Both natives use the direction-aware
spelling (SwiftUI `.leading`/`.trailing`, Compose `TextAlign.Start`/`.End`), so
an RTL locale would left-align on the web and trailing-align on iOS and Android
from the same `core.AlignStart`. The previous session deliberately kept the
physical keywords — "changing it is a rendering change, not a table change" —
and recorded the divergence in the table's doc comment. This session made the
rendering change.

---

## The change

Both DOM copies of the text-align table now emit CSS's direction-aware
keywords: `start` → `start`, `end` → `end` (previously `left`/`right`).
`center` and `justify` were already spelled the same on both sides.

That makes the table an **identity map on its four values** — core's text
alignment spellings now *are* the CSS ones, the same situation
`justify-content` and `align-items` were already in. But unlike those two, the
table cannot be deleted and the values passed through verbatim: it still earns
its keep as a **filter**, because the identity must not extend to `stretch` and
`baseline`, the two cross-axis-only Alignments that have to fall through to
`""` (no declaration from htmlout; property cleared by the runtime). Both
copies' comments now state that explicitly.

## Behavior actually changed

In LTR documents, nothing moves — `text-align: start` and `text-align: left`
render identically, which is exactly why the divergence survived unnoticed. In
an RTL document, `AlignStart` on a web-rendered node now trailing-aligns like
both natives instead of left-aligning. `text-align: start`/`end` is supported
in every evergreen browser; no fallback needed.

All four renderers now answer `core.AlignStart` and `core.AlignEnd` the same
way for the first time in any writing direction.

## The residual worth knowing

The divergence's **absence** is exactly as invisible to tests as its presence
was. The pin compares the two DOM copies with each other, and they agree under
either spelling; the census checks coverage, not meaning. The direction-aware
choice is guarded only by documentation — the table's doc comment and
wasm.md — which is the same class of unguarded fact as the four
SwiftUI/Compose *values* (backlog, below). A test that could see it would need
a real layout engine with a `dir="rtl"` document, i.e. a browser.
