## Item 1 — the window the other two leave between them

Two fingerprints already bracket this check. The tree one runs from the rects
to the last platform-font read and holds IDENTITY across it; the layout one
runs from the rects to the shutter and holds GEOMETRY across that. Between them
sits a window neither closes, and it is the one the faces are read in: from
`Page.captureScreenshot` to the last `CSS.getPlatformFontsForNode`.

A font that finished loading in there is what fits through it. It moves every
run's rect and changes no fact about which element is which, so the tree
fingerprint is silent and right to be; the layout question was asked and
answered at the shutter, so that one is silent too. What comes back afterwards
is the new face's glyph counts beside a capture painted with the old one —
`inkFaceFault`'s third arm reporting a substitution the pixels cannot show, or
a ligature census about a face the grid was not drawn in.

`faceLayoutFault` is the same expression compared across that third window, and
it costs no round trip: the tree fingerprint had to be taken there anyway, so
both ride back in one evaluate. Two round trips would have put a window between
the two readings that close the windows.

    the page relaid out under the 60 platform-font reads: the same 138 elements
    are at different rects (78fc975d then 281eb323)

`layoutMovedList` is the four ways a layout can differ, split out because the
list is the same for both windows and the consequence is not. `facesHeld` is
the one name every face consultation now asks, the way `pixelsHeld` is one name
for the two questions the sampling sites ask.

What it cannot see is a face swap that moved no mounted box — a font whose
metrics match, or text in a box whose size is declared. That is a miss and not
a false finding, and the run rects this scan holds are content-sized, so the
swap the window exists for is one that does move them. The comment says so.

Break-tests: the layout half dropped from the after-faces evaluate; a
`padding-top` applied between the shutter and the face reads, where the tree
fingerprint stays silent at 138 elements and the whole run is six lines —
one message, every face arm dropped.

## Item 2 — one face for the row to speak for

The census already refuses a row drawn by a family no run resolves. That is
"the row's family is one of the grid's", and what the row is being rested on is
"the row's family is the grid's". Eleven probes are eleven declarations, and
two of them differing in weight are two faces that may ligate differently —
while the check making the single row sufficient, `inkFaceFault`'s last arm, is
a per-pair claim about each box and ITS OWN probe. A conjunction of per-pair
claims is not the grid-wide one.

So the grid-wide claim is asked where it is being rested on:

    the grid's runs are drawn by 2 faces — Helvetica, Times — and the ligature
    row is one declaration (Times)

The tail recites "one platform face this browser names" and now says "one
across the whole grid", which it had been claiming and nothing had held.

Break-test: a second family added to the set the census is handed. That is a
value-level injection rather than a second face really mounted — mounting one
would move the rects and trip item 1's new window, which is a different finding
and would not reach this arm.

## Item 3 — a threshold with its argument in a comment

`inkReadShape` called a computed style anything with more than fifty string
values, with "a computed style is every longhand the build exposes — hundreds"
written beside it. The sentence is true and 50 is not derived from it: it is a
number that sits somewhere between hundreds and the four keys of a subject
read, and nothing said how far it was from either edge.

`INK_OWN_MEASURED_ON.props` is the one enumeration anybody here has counted —
476, on the build the exception table was assembled against — so the floor is a
quarter of it. What that buys is a number that MOVES when the file re-measures
against a newer Chrome, and room for a much narrower build before the shape
test stops recognising one.

And the derivation is checked against the running build, where `inkOwnRead`
knows what this browser actually enumerates. Under the floor the guard does not
fail, it goes QUIET — which the break-test shows exactly: `out.ownStyle`
written around the `declarations` table is caught on twenty bands at the
derived floor, and with the floor raised above this build's enumeration it is
caught nowhere and the new message is the only thing that says why.

Break-tests: the recorded enumeration raised to 4000 (the floor lands at 1000
over a 476-property build); the same with an out-of-manifest computed style
written into the read — 20 messages, then 0.

## Item 5 — every copy, not the first

`pinPhraseLines` took `FindStringIndex` and answered about one match. A phrase
is spelled twice whenever the sentence above an assertion quotes it, which is
the ordinary way a comment is written here — and the verdict is "is a surviving
copy on a line the lexer lost its place on". Over whichever copy came first,
that answers about the comment when the comment is above the code.

The break-test is the whole item. With the phrase quoted in prose above its own
assertion and an odd-quote regex blanking the assertion's line, the old code
said:

    the phrase is on [6847], which is not among them — so the blind spot is
    ruled out and what survives at that line is prose

and the new one says:

    the phrase, spelled 2 times in the file, is on [6848], which is among them
    — so this failure is pinCodeOnly's and not the harness's

The answer is grouped per spelling rather than flattened, because "on two
lines" and "twice" send a reader to different places; the caller flattens for
the verdict and counts the entries for the sentence.

Break-tests: `FindStringIndex` restored (the fixture's twice-spelled rows
fail); and the injection above, run against both versions.

## Item 7 — what the ceiling was costing

`cappedByReach` says a judgement and not these names decided the threshold. The
message went on to say "these names are far enough apart to carry a wider one",
which is a claim about crowding one step past the ceiling — and the search
stops at the ceiling without ever asking.

It was wrong about the very set the test was written around. Four "sparse"
names, and `Palette.Echo` has two siblings within four edits: the ceiling and
the crowding stop that set in the same place, and every reader of that message
was being sent to raise a constant that would find the crowd.

`afforded` continues the same upward search past the ceiling, bounded by the
longest leaf name — an edit distance is never more than the longer of two
strings, so past that every pair is inside the threshold and the answer stops
moving. Three arms, each now reached by a set with its shape:

    these names would carry 5 before a name at that distance could belong to
    more than one of them

    no parent here holds three leaves, so no width crowds these names at all

    and this struct's own crowding stops in the same place: 3 is the widest
    these names carry either way, so raising the ceiling would find nothing here

A set the ceiling did not stop reports `afforded == edits`, asserted over
core.Theme: the crowding already answered that question, and a second number
would be two measurements of one thing disagreeing.

Break-tests: the continuation disabled (four assertions fire); the old
unconditional sentence restored (all three message arms fire, including the
sparse set's).

   are ASCII pairs and the fixtures are Latin, so lowercasing is the whole of
   the normalisation — a fixture carrying a composed form, or a pair split by a
   zero-width joiner, would be refused by gen.go and reported by this note as
   not containing what it contains.
3. **(age 0 · value low) `INK_OWN_SHAPE_FLOOR` is a quarter and the quarter is

   the floor could be stated as sitting between two measured populations rather
   than as a fraction of one.
4. **(age 0 · value low) `bandtarget.mjs` owns the parts and browser.mjs owns

5. **(age 0 · value low) The phrase count is reported and the copies are not
