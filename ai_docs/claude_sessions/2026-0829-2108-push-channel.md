## Goal

Assess whether GrMob's architecture can support modern Android/iOS apps, then start
closing the gaps. The full analysis and five-step attack plan live in
`ai_docs/plans/grmob-mobile-feasibility-analysis.md`. This session completed attack-order
steps 1–3.

## Verdict from the analysis (short form)

Architecture is sound — it is React Native's original design with Go instead of JS. The
Go core is close; the gaps are the native renderer surface and the bridge's one-way,
synchronous shape. Key strategic call: render into Jetpack Compose / SwiftUI rather than
raw Views (their reconcilers handle identity, animation, recycling, a11y).

## Step 1 — Reconciler correctness (`reconcile/patch.go` + `patch_test.go`)

- `styleChanged` now compares by value (`reflect.DeepEqual`), not pointer. Every render
  re-allocates every `Style`, so the old `a != b` flagged every styled node as changed on
  every render.
- `propsChanged` uses `DeepEqual` per key (old `b[k] != v` panicked on slice/map props)
  and detects same-length maps with different key sets.
- `Diff(nil, nil)` no longer panics; nil child slots are safe.
- Sibling removals emitted highest-index-first so index-resolving renderers don't shift
  later targets.
- Removed dead `oldKeyed`/`newKeyed` maps and duplicated `if` block. Keyed mismatch still
  emits `replace` — true move patches need identity-based TargetIDs (positional paths
  can't express moves); documented on `Diff`.
- 18 table-driven tests; flagship: `TestDiffIdenticalTreesEmitNothing`.

## Step 2 — Stable callback IDs (`core/event.go`, `render/manager.go`)

- New `core.BeginRenderPass()` resets the three callback counters per render pass: the
  Nth callback registered in a pass is always `cb_N` / `txt_cb_N` / `bool_cb_N`.
  Unchanged UI ⇒ identical IDs ⇒ zero prop diffs. Registration overwrites with the
  latest closure (required anyway — new closures capture current state slots).
- Chose per-pass sequence IDs over path-derived: with positional diffing both shift under
  the same structural changes, so equal stability at far less machinery. Known limitation
  (documented on `BeginRenderPass`): an event against a stale tree can hit a reused ID;
  identity-keyed IDs fix this later.
- `PurgeUnusedCallbacks` (after diff) now has clean semantics: drops exactly the IDs not
  re-registered this pass.
- Latent bug fixed: empty patch list serialized as `null` (JS runtime does unchecked
  `forEach`); `RenderAgain` now guarantees `"[]"`.
- Tests: `core/event_test.go` (ID stability, distinct ID spaces, latest-closure-wins,
  purge), `render/manager_test.go` e2e (flagship: `TestNoOpReRenderProducesNoPatches`;
  a click patches ONLY the Text node at `root/0`).

## Step 3 — Go→native push channel

Discovery: the notification path was never connected — `State.Set` fired
`TriggerRender("default")` but registrations were keyed `render_N`, so it went into a
void; `UseInterval` only set an unwatched dirty flag.

- **Core** : `ctx.OnStateChange(fn)` registers the render driver under the default
  target; `ctx.RequestRender()` = MarkDirty + notify, the single "state changed" entry
  point. `State.Set` and interval ticks use it.
- **`render.Manager`**: `PatchListener` interface (one method, one string param —
  gomobile-bindable straight onto Kotlin/Swift). Pump goroutine fed by a buffer-of-1
  request channel: bursts of state writes coalesce into one render/one push. All render
  passes serialized behind `m.mu` (event path + pump). With no listener the pump never
  consumes a diff (would race/starve the WASM polling flow). `SetListener` flushes
  pre-attachment changes. `Close()` stops the pump.
- **`mobile/` package (new)**: gomobile-bindable facade — `Register`, `RenderInitial`,
  `SetListener`, `TriggerCallback/TriggerTextCallback/TriggerBoolCallback` (return patch
  JSON). Matches the surface `GrMobBridge.kt` expects. Delivery contract documented:
  each diff produced once, delivered on exactly one path (sync return or push).
- **WASM**: if the page defines `GrMobApplyPatches`, pushes go there; else polling
  unchanged.
- Tests: `render/push_test.go` (5 tests; headline
  `TestIntervalTickPushesWithoutAnyNativeEvent` — timer updates UI with zero native
  events), `mobile/bridge_test.go` round-trip. Stress-ran 5×, stable. WASM target
  compiles (`GOOS=js GOARCH=wasm`).

## Known caveats / open items

- **Data race remains**: `State.Set` writing a slot from a goroutine while a render reads
  it. Render passes are serialized, but mutations aren't marshalled onto one goroutine
  yet. Fold into the globals/threading cleanup before or alongside step 4.
- Package-level globals still present: `navigatorStack`, callback registries (Context has
  an unused `callbackMap` — consolidation pending).
- Pre-existing breakage (untouched): `examples/runtime/main.go:23` references
  `core.NewRuntime`, which doesn't exist anywhere.
- Android `GrMobBridge.kt` uses raw JNI `external fun` — inconsistent with the
  gomobile `build.sh`; the new `mobile/` package is the intended bind surface going
  forward.
