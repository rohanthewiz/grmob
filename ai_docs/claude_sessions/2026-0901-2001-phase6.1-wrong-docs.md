## Method

from the plan on faith. That caught two entries where the plan itself was
half-wrong (see below), and turned up four extra copies of the same defects
living in Go doc comments that the plan's table did not cite.

Edits were applied with `python3` heredocs asserting `count(old) == 1` on each
replacement, so a stale or duplicated anchor fails loudly instead of
silently patching the wrong place or nothing at all.

`[]StyleProp` into it even though the element type is assignable. The loop
that built `styles` is gone entirely.

### The pin

`examples/todoapp/tutorial_excerpt_test.go`. It re-reads the tutorial's
` ```go ` fences and checks that every fence naming this app's symbols traces
back to `app.go`/`store.go`.

"Traces back" is deliberately not byte equality — an excerpt may re-indent
(a fragment lifted out of `App`'s body is shown at the depth that reads best),
drop the source's inline comments (the tutorial paraphrases them in prose),
and elide with the tutorial's own `...` convention. The rule is: every
non-elided, non-comment line appears in the source **in order**, and a `...`
permits a gap.

Proven the Phase 1 way — `git stash push -- docs/tutorial-todo.md` with the
test kept, re-run: fails with exactly four findings (the entry row, `addTodo`,
`filterBar`, `todoRow`). Restored: passes.

## Two entries where the plan was wrong

Both fixed to what the code says, not to what the plan said.

- **#5** — plan: "`Scroll` and `List` have none either." `List` *does* have a
  theme base; it shares `Column`'s (`core/list.go:20`). The two containers
  without one are `Box` and `Scroll`, both by explicit design comment — a
  scroll region carrying the theme `Column`'s screen padding would inset every
  screen that wraps itself in one. The doc now says that.
- **#16** — plan: drop "Patch logging and inspection on every render" as
  nonexistent. *Inspection* exists: `reconcile.Diff` returns plain `[]Patch`,
  and `RenderAgain`/`TriggerCallback` hand the same set back as JSON. Only
  *logging* is missing (`grep` for `PatchLog|LogPatches|InspectPatch` is
  empty; the one `log.` in `render/` is the panic recovery). So README and
  ROADMAP now claim the half that is real, and the logging item moved from a
  `[x]` under Done to a `[ ]` under Planned › DevTools.

## Four extra sites the plan's table did not cite

The plan located #11 and #13 in `docs/components.md` only, but each claim had
a second copy in a widget's own doc comment; a sweep for the wording found
two more in `core`.

- `components/separator.go` — "neither renderer maps AlignItems `stretch`".
  Both do: Compose pins a stretched Row to `IntrinsicSize.Max` and gives each
  child `fillMaxHeight()`; SwiftUI's `GrMobFlexStack` proposes the full cross
  extent to a stretched child. So a `Vertical` field is now a **widget**
  change, not a renderer one. Recorded the asymmetry a future implementer
  needs: a Row reads `alignItems` alone and never the simpler `Align`
  fallback, so the containing row must spell out `AlignItems: "stretch"`.
- `components/progress_bar.go` — "proportional weights on iOS need a custom
  SwiftUI Layout, and when that lands this widget can move to flex."
  `GrMobFlexStack` **is** that Layout, with the arithmetic in
  `GrMobFlexSolver`. The widget has not been migrated, so the
  `containerRelativeFrame` caveat still describes today's behavior — the doc
  now says the blocker is gone and the migration is simply not done.
- `core/button.go:8` — the example quoted `theme.Danger` (#8's defect).
- `core/style_props.go:258` — the `Disabled` example quoted
  `form.Submitting` (#9's defect).

**No widget behavior changed.** Both widget comments now say "the blocker is
gone, the migration is not done" rather than describing a blocker that no
longer exists.
