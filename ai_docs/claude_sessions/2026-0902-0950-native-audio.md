## What landed

Audio is a **service**, not a node. A phone has one audio focus and one
lock screen, so the honest model is package-level functions and one status
record, and that is what makes background playback and remote controls
fall out of the platform instead of being reinvented per node.

- `core/audio.go` — `AudioLoad(track, opts...)`, `AudioPlay/Pause/Toggle`,
  `AudioSeek(s)`, `AudioSkip(delta)`, `AudioSetRate(r)`, `AudioStop()`,
  `CurrentAudioStatus()`, `OnAudioStatus(fn)`. Commands leave as **one**
  system event named `"audio"` with a `command` field. Load and Stop update
  the record optimistically (loading / idle); everything else is the host's
  word. Skip is relative on the host side because core's position is up to
  a tick stale.
- `core/host_events.go` — the reverse channel, generic: `ReceiveHostEvent`
  consumes core's own names first (`audio_status`) then fans out to
  `OnHostEvent` subscribers. `mobile.ReportHostEvent(name, json) string`
  returns patches like `Trigger*`; `render.Manager.Dispatch(label, fn)` is
  the lock-and-render primitive behind it (returns `"[]"` before mount).
  `GrMobWASM.HostEvent` is the browser entry.
- `hooks.UseAudio(ctx)` — subscribes once per slot, `RequestRender` per tick,
  released on `ctx.Close` (drain semantics like `UseInterval`).
- `core.Slider(value, min, max, onChange, ...)` + `OnSliderChangeEnd` +
  `SliderStep` — a range control on all four targets; the natives show the
  finger's value while dragging (the text-field compromise) so status ticks
  never snap the thumb.
- Hosts: Android = Media3 1.4.1 ExoPlayer inside `GrMobAudioService`
  (`MediaSessionService`) driven by a `MediaController` from `AudioPlayer.kt`
  (commands queue until the controller connects); iOS = `AVPlayer` +
  `MPNowPlayingInfoCenter` + `MPRemoteCommandCenter` + `.playback`/`.spokenAudio`
  session + interruption handling, `UIBackgroundModes: [audio]`; browser =
  `HTMLAudioElement` + Media Session API inside `grmob-runtime.js`.
- `examples/mobileapp` gained an Audio tab (SoundHelix sample) — the smoke
  test for both natives.

## Gotchas found on the way

- The hosts keep their playback rate across a stop (ExoPlayer's
  `playbackParameters`, `AVPlayer.defaultRate`, the element's
  `playbackRate`), but Go's record resets to 1 — so each host resets the
  rate on `stop` before reporting, or the label shows 1.25× on nothing.
- `core.Justify(core.JustifyBetween)` on a `Row` needs `core.Width("100%")`
  on the natives, or the Row hugs its children and there is nothing to
  distribute.
- A range input clamps its value at assignment time to the bounds it has
  *then* (default 0..100), so the runtime applies `min/max/step` as
  attributes and re-assigns the value after them (`applySliderBound`).
- Android 13+ shows a MediaSession notification without
  `POST_NOTIFICATIONS`; what Android 14 needs is
  `FOREGROUND_SERVICE_MEDIA_PLAYBACK` and `foregroundServiceType`.
